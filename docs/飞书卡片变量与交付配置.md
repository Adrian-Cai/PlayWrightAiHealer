# 飞书卡片变量与交付配置

## 目的

本文档用于交付 Playwright AI Healer 的飞书通知能力。接手人可按照本文完成飞书卡片搭建、环境变量配置和验收，无需阅读实现代码。

## 三类通知的边界

| 通知 | 接收人 | 是否使用飞书模板 | 是否需要在飞书后台配置变量 |
| --- | --- | --- | --- |
| 测试结果汇总 | `FEISHU_CHAT_ID` 群聊 | 否 | 否 |
| Locator 审批 | `FEISHU_REVIEWER_OPEN_ID` 私聊 | 可选，推荐使用模板 | 是，首次搭建时配置一次 |
| 自愈过程 | 默认不发飞书 | 否 | 否 |

自愈过程持续写入 `test-results/ai-healer-events.jsonl`。仅当 `FEISHU_SEND_HEAL_EVENTS=true` 时才会逐条发送飞书卡片，不建议在常规运行中开启。

## 环境变量

在仓库根目录 `.env` 中填写：

```env
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_CHAT_ID=oc_xxx
FEISHU_REVIEWER_OPEN_ID=ou_xxx
HEALER_CALLBACK_TOKEN=replace-with-a-random-secret

# Locator 审批卡使用飞书卡片模板时填写；留空则使用代码内置卡片。
FEISHU_REVIEW_CARD_TEMPLATE_ID=AAqxxxxxxxx
```

| 变量 | 用途 | 获取方式 |
| --- | --- | --- |
| `FEISHU_CHAT_ID` | 接收测试结果汇总的群 ID | 在目标群中获取 `chat_id`，并确保机器人已入群且可发言 |
| `FEISHU_REVIEWER_OPEN_ID` | 接收 Locator 审批私聊的负责人 ID | 从飞书用户信息或事件回调中获取该应用下的 `open_id` |
| `FEISHU_REVIEW_CARD_TEMPLATE_ID` | Locator 审批卡模板 ID | 在飞书卡片搭建工具发布模板后复制模板 ID |
| `HEALER_CALLBACK_TOKEN` | 审批按钮的额外校验密钥 | 使用随机字符串；必须与回调服务使用的值一致 |

`.env` 含密钥，禁止提交到 Git。

## 卡片 1：测试结果汇总

### 卡片内容

群聊卡片仅显示以下四项：

| 字段 | 数据来源 |
| --- | --- |
| 测试总数 | Playwright reporter 统计 |
| 通过 | Playwright reporter 统计 |
| 失败 | Playwright reporter 统计 |
| 跳过 | Playwright reporter 统计 |

该卡片不显示自愈明细、不显示测试报告链接，也没有操作按钮。

### 配置要求

无需在飞书卡片搭建工具创建模板或变量。只需设置 `FEISHU_CHAT_ID`。

## 卡片 2：Locator 审批

### 选择模板模式

未设置 `FEISHU_REVIEW_CARD_TEMPLATE_ID` 时，系统发送代码内置的审批卡。

设置 `FEISHU_REVIEW_CARD_TEMPLATE_ID` 后，系统改为发送飞书卡片模板。模板中的变量名、类型和层级必须与下表完全一致，名称区分大小写。

### 顶层变量

| 变量名 | 类型 | 绑定位置 | 示例模拟数据 |
| --- | --- | --- | --- |
| `review_title` | 文本 | 卡片标题 | `Playwright AI 自愈待审核` |
| `review_summary` | 文本 | 标题下方概览文本 | `测试 3 项：通过 2，失败 1，跳过 0。待审核定位器 1 项。` |
| `proposal_items` | 对象数组 | 循环容器的数据源 | 见下方完整示例 |

### `proposal_items` 的子变量

在飞书卡片搭建工具中添加“循环容器”，将其对象数组变量命名为 `proposal_items`。再在该对象数组的变量结构中创建以下子变量。

| 子变量名 | 类型 | 绑定位置 | 数据来源 |
| --- | --- | --- | --- |
| `index` | 整数 | 序号文本 | 当前卡片中的提案序号，从 1 开始 |
| `element_name` | 文本 | 元素名称 | 测试代码传入的元素描述 |
| `test_name` | 文本 | 用例名称 | Playwright `testInfo.title` |
| `locator_key` | 文本 | Locator Key | `locator-store.json` 的 key |
| `action` | 文本 | 操作类型 | `click`、`assert`、`fill`、`locate` 等 |
| `old_locator` | 文本 | 旧定位器 | 原始失败 locator |
| `new_locator` | 文本 | 新定位器 | AI 候选 locator，通过质量门禁后写入提案 |
| `confidence` | 文本 | 置信度 | 例如 `92%` |
| `reason` | 文本 | 修复理由 | AI 返回的原因 |
| `approve_value` | 对象 | “确认替换”按钮的 `value` | 审批回调参数 |
| `reject_value` | 对象 | “拒绝”按钮的 `value` | 拒绝回调参数 |

两个按钮必须位于循环容器内部，分别将其 `value` 属性绑定到 `approve_value` 和 `reject_value`。按钮文案可固定为“确认替换”和“拒绝”，无需作为变量。

### 模拟数据

在飞书搭建工具的“模拟数据”中使用以下数据预览模板：

```json
{
  "review_title": "Playwright AI 自愈待审核",
  "review_summary": "测试 3 项：通过 2，失败 1，跳过 0。待审核定位器 1 项。",
  "proposal_items": [
    {
      "index": 1,
      "element_name": "批量确认按钮",
      "test_name": "人工确认-批量确认按钮校验",
      "locator_key": "batchConfirmButton",
      "action": "assert",
      "old_locator": "text=批量确认",
      "new_locator": "button:has-text(\"批量确认\")",
      "confidence": "92%",
      "reason": "页面中唯一匹配且元素可见",
      "approve_value": {
        "action": "approve_locator",
        "proposalId": "proposal-demo-001",
        "token": "demo-token"
      },
      "reject_value": {
        "action": "reject_locator",
        "proposalId": "proposal-demo-001",
        "token": "demo-token"
      }
    }
  ]
}
```

运行时会覆盖这些模拟数据；不需要将真实旧 locator、新 locator 或 token 手工填写进模板。

### 搭建步骤

1. 在飞书卡片搭建工具新建并发布 Locator 审批模板。
2. 添加标题和概览文本，分别绑定 `review_title`、`review_summary`。
3. 添加循环容器，数据源绑定 `proposal_items`。
4. 在循环容器内添加元素名称、用例、旧 locator、新 locator、置信度和理由等文本组件，并绑定对应子变量。
5. 在循环容器内添加“确认替换”和“拒绝”按钮；分别绑定 `approve_value`、`reject_value` 到按钮 `value`。
6. 使用上方模拟数据预览并确认一项提案的布局、两种按钮和回调值均正确。
7. 发布模板，复制模板 ID 到 `.env` 的 `FEISHU_REVIEW_CARD_TEMPLATE_ID`。
8. 重启测试进程和 `npm run feishu:callback`，使新环境变量生效。

系统每张审批卡最多展示 10 个待审核提案；同一提案的确认或拒绝会通过回调服务更新 `locator-store.json` 或提案状态。

## 卡片 3：自愈过程

默认策略是“不发卡片，保留审计记录”。自愈过程写入：

```text
test-results/ai-healer-events.jsonl
```

该文件可作为 Jenkins 构建产物归档，记录事件类型、用例、页面 URL、原 locator、候选 locator、置信度、质量门禁结果和错误信息。

如确有调试需求，可设置：

```env
FEISHU_SEND_HEAL_EVENTS=true
```

开启后使用代码内置事件卡片，不依赖飞书模板变量。常规 CI 不建议开启，以避免群聊刷屏。

## 发布前验收

1. 在测试环境运行一次会产生 pending Locator 提案的用例，确认负责人收到私聊审批卡。
2. 检查卡片中旧 locator、新 locator、置信度和理由是否正确显示。
3. 点击“确认替换”，确认 `locator-store.json` 被更新；点击“拒绝”，确认 locator 不变。
4. 运行普通测试，确认群聊只收到四项统计的汇总卡，无报告按钮和自愈明细。

## 常见问题

| 现象 | 检查项 |
| --- | --- |
| 模板变量为空 | 检查变量名、对象层级和类型是否与本文一致；变量名区分大小写 |
| 审批卡未发送 | 检查 `FEISHU_REVIEWER_OPEN_ID`、应用可用范围和机器人私聊权限 |
| 按钮点击后无效果 | 检查 `npm run feishu:callback` 是否运行，及 `HEALER_CALLBACK_TOKEN` 是否一致 |
| 仍然使用内置卡片 | 检查 `FEISHU_REVIEW_CARD_TEMPLATE_ID` 是否已写入 `.env` 并重启进程 |
| 群聊出现报告链接 | 检查运行的是最新代码；群汇总卡不应包含报告链接 |
